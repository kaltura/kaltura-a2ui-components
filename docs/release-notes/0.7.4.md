## 0.7.4: the player's startTime now seeks, and clipFrom cuts a segment

The Player's `startTime` was sent to the Kaltura Player as `seekFrom`. That is a clip parameter, so an entry with one MP4 flavor ignored it and played from 0. A live run with the Claude Haiku 5.5 demo found it. `startTime` now seeks on load. A new `clipFrom` prop cuts the video, so the timeline runs from 0 to the clip length. The catalog changed.

### Changed

| Prop | Before | Now |
|---|---|---|
| `startTime` | Sent as `seekFrom`. It cut the stream and was ignored for single-flavor entries | Seeks on load. The whole entry stays available and the timeline shows its full length |
| `clipFrom` | None | New. Cuts the video to start here. Use it with `clipTo` to show a segment |
| `clipTo` | Cut the end | Same. The timeline ends here, or at the clip length with `clipFrom` |

`startTime` with `clipFrom` counts from the clip start. Flashcard clips are unchanged: they still cut with `startTime` and `endTime`, and their descriptions now say so.

A clip start needs an entry with an HLS or DASH stream. An entry with one progressive file honors `clipTo` and ignores `clipFrom`.

### Tests

LIVE-02 checks that `startTime` seeks and `clipTo` ends playback, with no `clipFrom` in the request. The new LIVE-02b plays a real clip and checks that the timeline runs from 0 to the clip length.
